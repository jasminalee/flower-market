- **后端应用:** SpringBoot REST API 服务
- **数据库系统:** MySQL 关系数据库
- **外部集成:** 支付网关、物流系统、第三方服务

### 1.2 测试目标

#### 1.2.1 主要目标

| 目标 | 具体内容 |
|-----|---------|

### 2.3 性能测试

#### 2.3.1 测试描述

验证系统在不同负载条件下的性能表现，包括响应时间、吞吐量、资源利用率等。

#### 2.3.2 性能测试指标

| 指标 | 目标值 | 测试方法 | 优先级 |
|-----|--------|---------|--------|
| API 平均响应时间 | < 500ms | 并发请求测试 | P0 |
| 页面加载时间 | < 2s | 浏览器性能监测 | P0 |
| 系统吞吐量 | ≥ 1000 req/s | 压力测试 | P1 |
| 数据库查询响应时间 | < 100ms (P95) | 数据库监控 | P1 |
| CPU 使用率 | < 80% | 系统监控 | P1 |
| 内存使用率 | < 80% | 系统监控 | P1 |
| 并发用户数 | ≥ 5000 | 并发测试 | P2 |

#### 2.3.3 性能测试场景

**基准测试**
- 单个用户正常操作的响应时间

**负载测试**
- 100、500、1000、5000 并发用户的系统表现

**压力测试**
- 提升并发用户数至系统瓶颈，观察系统行为

**耐久性测试**
- 中等负载（如 1000 并发）下持续运行 24 小时，监控内存泄漏、连接泄漏等

```bash
# 1. 克隆项目代码

mvn clean install -DskipTests

# 2.2 配置数据库
# 编辑 application.yml，配置 MySQL 连接信息

# 2.3 初始化数据库
mysql -u root -p < src/main/resources/schema.sql
mysql -u root -p < src/main/resources/data.sql

# 3. 前端环境配置
cd ../frontend

# 3.1 安装依赖
npm install
# 或
yarn install

# 3.2 启动开发服务器
npm run dev
# 或
yarn dev

# 4. 访问应用
# 前端: http://localhost:5173 (Vite 默认端口)
# 后端 API: http://localhost:8080 (Spring Boot 默认端口)

## 4. 测试数据准备方法

### 4.1 测试数据总体策略

#### 4.1.1 数据准备原则

```
原则 1: 真实性
----------------------------------------------
测试数据应尽可能接近生产数据的特征

示例:
- 真实的商品信息（名称、价格、分类）
- 符合业务规则的订单状态转变
- 真实的地理位置信息


原则 2: 孤立性
----------------------------------------------
测试数据必须与生产数据完全隔离

要求:
- 使用独立的数据库账户和数据库
- 测试数据标记唯一标识符（如 _TEST_ 后缀）
- 定期清理测试数据


原则 3: 完整性
----------------------------------------------
测试数据覆盖所有主要业务场景

场景:
- 正常流程（Happy Path）
- 异常流程（Exception Path）
- 边界条件（Boundary Conditions）
- 交叉场景（Cross-module Scenarios）


原则 4: 可回溯性
----------------------------------------------
测试数据的来源和变化过程可追踪

实施:
- 记录数据版本和更新日期
- 保留测试数据变更日志
- 备份重要的测试数据集
```

/**
 * 数据脱敏工具类
 */
public class DataMaskingUtil {
    
    /**
     * 脱敏手机号
     */
    public static String maskPhone(String phone) {
        if (phone == null || phone.length() < 6) return phone;
        return phone.substring(0, 3) + "****" + phone.substring(7);
    }
    
    /**
     * 脱敏邮箱
     */
    public static String maskEmail(String email) {
        int atIndex = email.indexOf("@");
        if (atIndex <= 1) return email;
        String prefix = email.substring(0, 1);
        String domain = email.substring(atIndex);
        return prefix + "***" + domain;
    }
    
    /**
     * 脱敏身份证
     */
    public static String maskIdCard(String idCard) {
        if (idCard == null || idCard.length() < 8) return idCard;
        return idCard.substring(0, 6) + "****" + idCard.substring(14);
    }
}

### 6.3 缺陷统计与分析

#### 6.3.1 缺陷统计指标

```
关键指标
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 缺陷发现速率
   定义: 每日平均发现的缺陷数
   计算: 本周期发现缺陷总数 ÷ 测试天数
   
   示例:
   假设总共发现 150 个缺陷，测试周期为 15 天
   
   发现速率 = 150 ÷ 15 = 10 个/天
   
   评估:
   - 速率上升：功能开发质量可能有问题
   - 速率下降：缺陷空间逐渐被填补

2. 缺陷修复速率
   定义: 修复的缺陷占已发现缺陷的百分比
   计算: (已修复缺陷数 ÷ 已发现缺陷数) × 100%
   
   示例:
   已修复：120 个，已发现：150 个
   
   修复速率 = (120 ÷ 150) × 100% = 80%

3. 缺陷趋势分析
   
   缺陷发现与修复趋势图
   
   缺陷数
   │        ┌─────────────┐
   │        │ 发现曲线   │
   │      ╱ │             │
   │    ╱   │             │
   │  ╱     └─────────────┘
   │╱
   │     ╱─────┐        ┌┐
   │    ╱       └──┐  ┌──┘│ 修复曲线
   │   ╱           └──┘    │
   │  ╱                    └─────
   │╱
   └─────────────────────────  时间
   
   解读:
   - 当修复曲线逼近发现曲线时，缺陷存量减少
   - 缺陷发现速率持续下降至接近零时，测试充分度相对稳定

4. 缺陷分布
   
   按优先级分布
   P0: 5%  (7/150)    阻塞性缺陷
