1 简介

1.1 项目背景

花卉消费市场目前正从季节性购买向日常消费发生重大转变。随着社会经济的发展和居民生活质量的提高，花卉已从传统的仪式性礼品演变为日常审美生活的重要组成部分，成为提升生活质量与环境装饰的关键元素。这种消费模式的转变使消费者对更全面、更专业的花卉购买体验提出了需求，包括多元化的产品选择、透明的产品溯源、准确的配送服务以及专业的养护指导。



在行业供给侧，传统花艺零售模式面临数字化转型压力。作为行业主体的中小型花店普遍遇到以下发展瓶颈：实体经营受限于固定营业时间和有限服务区域，难以突破地域限制拓展客户群体；依赖人工记录的订单管理和库存盘点方式效率低下且易出错；缺乏有效的数字化客户关系管理工具，阻碍了稳定会员体系的建立和精准营销策略的实施。



尽管现有的综合性电子商务平台为花店提供了线上销售渠道，但它们的通用设计架构存在显著缺陷：复杂的操作流程需要员工具备更高的技术技能；平台佣金成本挤压本就有限的利润空间；最重要的是，缺乏针对花卉产品特点设计的专用功能模块，无法满足花业在库存管理、产品展示和维护服务等方面的特殊需求。



基于这一市场状况和技术差距，本项目旨在开发一个专为花业设计的垂直电子商务平台。该平台将通过数字技术重构花店的运营模式，为消费者创造专业便捷的花卉购物体验，同时为花店提供轻量级、用户友好的管理工具。这将有效推动传统花卉零售业务的数字化转型和升级，支持整个行业的健康可持续发展。

1.2 项目目标



该项目旨在开发一个基于 SpringBoot 的鲜花电子商务平台，以支持中小型花店的数字化转型并优化消费者购物体验。具体目标包括：提高运营效率、增强用户体验、推动行业数字化、建立会员和营销系统，以及确保系统可靠性和可扩展性。

1.3 项目背景与范围

花卉行业目前正处于数字化转型的关键节点，传统中小型花店迫切需要通过专业的管理系统升级其运营模式。本项目旨在开发一个专为花卉行业设计的垂直电子商务平台，帮助花店从传统的手动管理向数字化管理转型，从而提升其市场竞争力。

2 驱动问题

本项目的驱动问题是：“如何利用软件工程技术来开发支持人类活动的软件系统？”在本花市系统项目中，软件工程技术被应用于多个方面，以有效支持消费者和小型、中型花店经营者的活动。

首先，在系统设计阶段，使用了面向对象的分析和设计技术。通过将花零售行业的现实实体，如用户、产品、订单等，建模为类和对象，系统可以更好地模拟实际业务流程。例如，产品类包括如花期和养护难度等专业属性，这些属性符合花产品的特点，使系统能够准确表示和管理与花相关的信息，从而支持花店经营者的产品管理活动。

其次，采用前后端分离架构（后端使用 SpringBoot，前端使用 Vue.js）是软件架构设计技术的典型应用。这种架构将表现层与业务逻辑层分离，使得前端和后端可以独立开发和维护。对于用户而言，前端响应式设计确保了在不同设备上都能获得流畅的购物体验，支持他们的多渠道购物活动。对于开发者而言，它促进了并行开发，提高了开发效率，并支持了项目团队的合作开发活动。

其次，采用了敏捷开发方法，这是软件工程的关键过程技术。通过迭代开发和测试，项目团队可以持续从用户（花店经营者和消费者）那里收集反馈，并及时调整系统。例如，在每个迭代中，可以开发并测试新功能，并根据用户反馈优化现有功能。这确保了最终系统能够更好地满足用户的实际需求，有效支持他们的日常运营和购物活动。

此外，软件测试技术在支持人类活动中发挥着关键作用。采用多种测试方法，如单元测试、集成测试和系统测试，以确保系统的可靠性和稳定性。对于花店经营者，稳定的系统确保了订单处理和库存管理等日常运营的顺利进行，避免了因系统故障造成的损失。对于消费者，它保证了无障碍的购物体验，增强了他们对平台的信任。

数据管理技术，包括使用 MySQL 进行关系型数据存储和 Redis 进行缓存，也支持人类活动。高效的数据存储和检索确保花店经营者能够快速访问和管理业务数据，例如查询库存水平和销售统计，从而做出明智的商业决策。对于消费者而言，快速的数据加载速度减少了页面等待时间，提高了他们的购物效率。

综上所述，通过在系统设计、架构、开发方法、测试和数据管理中应用一系列软件工程技术，该花市系统有效地支持了中小型花店的日常运营和消费者的购物活动，回答了驱动问题。



































































3 问题发现

3.1 产品信息依赖人工记录，容易出错且难以维护

线下花店通常采用人工方法记录产品信息。对于鲜花、绿植和多肉植物等商品，统一且准确地数字化管理名称、价格和属性等方面存在挑战，尤其缺乏对开花期和维护特性等专业属性的管理。

**解决方案：建立统一的数字化产品信息管理系统**

实现产品信息的统一数字化管理，支持多维分类和专业属性管理，为后续的库存和订单等流程提供准确的数据基础。

3.2 无法建立会员体系，导致客户留存率低

线下花店难以建立有效的会员系统，导致无法识别和留住用户身份。这阻碍了精准营销和个性化服务的任何努力，结果导致顾客大多是单次交易。



**解决方案：建立用户注册和登录系统**

提供安全的身份认证机制，支持多渠道登录以降低门槛，为建立会员系统并提升客户终身价值打下基础。





3.3 用户需要反复下单，导致购物体验不佳

尤其是在礼品花束组合等场景中，用户无法临时保存或批量处理所需商品，需要反复提交订单。这导致流程繁琐，购买效率低下。



**解决方案：部署购物车功能**

支持商品批量操作和实时价格计算，临时保存用户选择，简化购买流程，有效提升购买转化率和用户体验。

3.4 订单管理混乱，易出错和丢失

线下花店订单管理依赖人工记录，常导致混乱、遗漏或丢失。在节假日等高峰期，订单处理效率低下且错误频发。

**解决方案：创建全流程订单管理系统**

提供完整的订单状态跟踪和自动化处理，支持预约送花等特殊需求，提升处理效率并增强用户信任。

3.5 库存依赖人工盘点，效率低下且易出错

线下花店采用人工盘点库存，效率低下且容易出错。这常常导致热门花卉缺货或易腐商品积压，造成损失。

**解决方案：建立智能库存管理模块**

实施实时库存监控和预警机制，支持批量管理和智能补货建议，确保数据准确性并降低库存风险。

3.6 严重客户流失和低复购率

线下花店缺乏有效的客户留存方法，导致交易后难以重新吸引用户，造成严重的客户流失和低复购率。



**解决方案：引入会员积分和等级制度**

通过积分激励和会员等级提升用户粘性和忠诚度，支持积分兑换，构建会员生态的良性循环。

3.7 新客户缺乏决策参考，导致转化困难

尤其是对于鲜花等视觉产品，新用户在没有用户评价的情况下难以做出购买决策，导致难以建立信任。

**解决方案：建立产品评价和展示系统**

展示真实用户评价和图片，收集用户反馈，在用户之间建立信任桥梁，降低决策门槛，提高转化率。

3.8 运营决策缺乏数据支持，依赖经验

店铺经营者无法实时掌握销售、订单量、热门产品等关键业务指标，导致难以进行科学数据分析与策略优化。

**解决方案：提供数据统计与分析仪表盘**

实时监控关键业务指标，提供多维度的销售数据分析，支持数据驱动的运营决策与精细化管理。

3.9 促销活动效率低下，效果不佳

线下花店促销方式单一且效率低下，难以有效刺激消费、提高客单价和增加销量，尤其在节假日营销期间。

**解决方案：建立灵活多样的优惠券系统**

通过发行各类优惠券刺激消费，实现精准营销，提升促销活动效果，增强市场竞争力。

3.10 供应商信息混乱，导致采购成本高

花店供应商信息管理混乱，采购流程低效，缺乏供应商质量与绩效评估体系，影响货源质量与成本。

**解决方案：建立数字化供应商管理系统**

优化采购流程，建立供应商评估体系，支持价格比较与绩效管理，确保货源质量，降低采购成本。

3.11 消费者缺乏维护知识，影响体验

购买鲜花后，消费者缺乏专业的养护指导，导致鲜花快速枯萎，体验不佳，并可能引发售后问题，集中体现了“易买难养”的问题。

**解决方案：创建专业鲜花养护知识库**

提供不同场景下的专业养护指导，减少售后问题，提升平台的专业价值与用户粘性，打造差异化的竞争优势。

3.12 用户无法保存心仪产品，阻碍复购

用户无法有效收集或记录他们感兴趣的产品，尤其是在有周期性送礼需求的情况下，这不利于促进重复购买。

**解决方案：添加产品收藏和通知功能**

允许用户管理感兴趣的产品，支持降价提醒，为个性化推荐提供数据基础，增加销售机会，并提高用户活跃度。

3.13 产品质量信息不透明，难以建立信任

消费者对花产品的质量信息，如产地和种植过程缺乏了解，这影响了购买信心，也难以建立品牌信任。

**解决方案：展示产品可追溯信息**

直观展示产品产地和种植过程等可追溯信息，提升产品可信度和品牌透明度，并创造差异化的竞争优势。

3.14 用户选择困难，决策成本高

面对种类繁多的花卉产品，用户容易在选择上感到困扰，尤其是对于情感驱动的产品如花卉，这会降低浏览和购买效率。

**解决方案：引入智能热门推荐功能**

根据用户行为、季节和节日提供智能推荐，增加产品曝光，帮助用户发现更多感兴趣的产品，提升销售转化和体验。

3.15 缺乏用户互动，难以培养忠诚度

花店与其用户之间缺乏日常、轻量级的互动机制，导致访问频率低，难以培养和维持用户忠诚度。

**解决方案：建立会员签到积分系统**

通过签到等简单机制培养用户习惯，增加平台访问频率，收集行为数据，加强用户互动和忠诚度。





4 系统需求与架构

4.1 所提出的系统的整体架构

所提出的鲜花市场系统采用 B/S（浏览器/服务器）架构，并实现前后端分离，以增强可扩展性和可维护性。

4.1.1 前端架构

前端使用 Vue.js 以及 Element-UI 组件库进行开发，提供了丰富的 UI 组件并支持响应式设计。前端分为三个主要模块：用户端、商家端和管理员端。每个模块具有独立的页面路由和状态管理。使用 Vue Router 进行页面路由管理，实现平滑的页面切换和导航。使用 Vuex 进行状态管理，确保不同组件之间数据的一致性共享。前端通过 RESTful API 与后端通信，发送请求并接收响应以实现数据交互。此外，前端使用 Axios 进行 HTTP 请求处理，实现请求拦截和响应拦截等功能，以统一处理请求头、认证和错误响应。



4.1.2 后端架构

后端使用 Spring Boot 框架构建，简化了 Java 应用程序的开发和部署。后端遵循分层架构，包括表示层、业务逻辑层、数据访问层和领域模型层。

• 表示层：该层负责接收前端请求并返回响应。它使用 Spring MVC 实现 RESTful API，处理请求参数、数据验证和响应格式。JWT（JSON Web Token）用于用户认证和授权，确保 API 访问的安全性。

• 业务逻辑层：该层包含系统的核心业务逻辑，如产品管理、订单处理和库存控制。它通过服务类实现，服务类调用数据访问层的方法对数据库进行操作并实现业务规则。事务管理用于确保业务操作的一致性，例如在创建订单时同时减少库存。

• 数据访问层：该层负责与数据库交互。它使用 MyBatis 作为 ORM（对象关系映射）框架，将数据库表映射到 Java 对象，简化数据库操作。数据访问层提供添加、删除、修改和查询数据的方法，这些方法被业务逻辑层调用。

• 域模型层：该层定义与数据库表对应的实体类，如 User、Product、Order 和 Inventory。这些实体类包含相应实体的属性，并提供数据访问的 getter 和 setter 方法。



4.1.3 数据存储架构

该系统使用 MySQL 作为关系型数据库来存储核心业务数据，例如用户信息、产品数据、订单记录和库存数据。MySQL 提供可靠的数据存储和高效的查询能力，支持复杂的 SQL 操作和事务管理。为了提高系统性能，特别是热门产品数据的访问速度，使用 Redis 作为缓存数据库。Redis 缓存频繁访问的数据，例如热门产品信息和用户会话数据，减少数据库访问次数，提高系统的响应速度。



4.1.4 部署和安全架构

Nginx 被用作静态资源服务器和反向代理服务器。作为静态资源服务器，它存储并服务前端页面、图像和视频等静态资源，减轻后端服务器的负载。作为反向代理服务器，它将客户端请求分发到多个后端服务器，实现负载均衡并提高系统的并发处理能力。此外，Nginx 提供 HTTPS 加密等安全功能，防止传输过程中的数据泄露。系统还实施输入验证、SQL 注入防护和 XSS（跨站脚本攻击）防护等安全措施，以确保系统的安全性和稳定性。

4.2 系统范围

基于 SpringBoot 的花卉交易平台将专注于满足花卉零售行业中小型花店和消费者的核心需求。具体范围包括：

商家端：系统将涵盖商品管理（包括对开花期和养护难度等独家属性的管理）、库存管理（实时监控、批量管理、库存预警）、订单管理（订单状态跟踪、自动处理、定时配送）、客户管理（会员体系、积分管理、用户标签）以及数据统计（销售统计、热销商品分析、运营看板），帮助商家实现日常运营的数字化管理，提升效率并降低成本。

消费者端：系统将提供商品浏览和搜索（多维分类、精确检索）、商品详情查看（包括可追溯信息、维护指南）、购物车（批量操作、实时价格）、订单下单和跟踪（预约配送、物流查询）、会员权益（积分累积和兑换）、商品评价（评分、图片分享）以及个性化推荐（基于用户偏好和购买历史），提升消费者的购物体验，提供透明信息和便捷服务。

系统不包括大规模花材批发所需的复杂供应链管理（如全球采购、多级分销），也不涉及需要线下互动和专业设计软件集成的高端定制花艺服务，因为该项目的核心是为中小型花店提供轻量级和通用的解决方案。

4.4 非功能性需求

4.4.1 性能需求

响应时间：页面加载时间≤3秒，关键操作响应时间≤2秒。

并发处理：支持至少1,000个同时在线用户和500个并发用户操作。

数据处理：大规模数据查询响应时间≤5秒。

系统容量：支持至少100,000条产品记录和数百万条用户记录。

4.4.2 安全要求

数据加密：用户密码使用 BCrypt 加密，敏感数据通过 HTTPS 传输。

访问控制：基于角色的访问控制（RBAC），为用户提供不同权限。

攻击防护：防范常见网络威胁（例如，SQL 注入，XSS 攻击）。

数据备份：定期自动备份，支持灾难恢复。

4.4.3 可靠性要求

系统可用性：99.9%正常运行时间，年停机时间不超过8小时。

故障恢复：系统故障后30分钟内恢复服务。

数据一致性：确保分布式环境中数据的最终一致性。

容错性：单点故障不会影响整体系统运行。

4.4.4 可用性需求

用户界面：简单直观的界面，具有用户友好的工作流程。

设计。

运营效率：常用操作在3步内完成。

文档：全面的在线帮助和用户指南。

4.4.5 可维护性要求

代码规范：遵循统一的编码规范和设计模式。

模块化设计：系统模块间低耦合，便于独立维护和升级。

日志记录：完整记录操作和系统日志，用于追踪。

监控与告警：实时系统监控，异常情况自动告警。

4.4.6 可扩展性要求

架构：基于微服务架构，支持水平扩展。

API 标准：为第三方集成提供标准化的 API 接口。

插件机制：支持功能模块的插件扩展。

配置灵活性：系统参数可通过配置文件调整。

4.4.7 兼容性要求

浏览器兼容性：支持主流浏览器（Chrome、Firefox、Safari、Edge）。

移动设备兼容性：可在 iOS 和 Android 系统上使用。

分辨率自适应：支持多种屏幕分辨率的自适应显示。

数据格式兼容性：支持常见数据格式的导入/导出。

4.4.8 用户体验需求

页面加载：优化首屏加载时间，采用渐进式图像加载。

交互式反馈：即时操作反馈和加载状态指示器。

错误处理：用户友好的错误消息及建议解决方案。

个性化服务：基于用户行为的推荐内容。

4.5 数据描述

4.5.1 用户数据

基本信息：包括用户名、加密密码、电话号码（唯一验证）、个人头像（以 URL 形式存储）、性别（男/女）和出生日期（用于个性化生日促销）。

地址信息：一个配送地址簿，包含收件人姓名、电话号码、详细地址（省/市/区/街道和门牌号）、邮政编码和地址标签（家/办公室/其他），支持设置默认地址。

行为数据：浏览历史（产品 ID、查看时间、持续时间）、搜索历史（搜索关键词、搜索时间）、产品收藏（收藏的产品 ID、收藏时间）和签到记录（签到日期、获得的积分）。

会员系统数据：积分余额（总累计积分）、会员等级、成长值（用于等级升级）和优惠券持有情况（优惠券 ID、类型、价值、使用条件、有效期）。

特殊字段：用户花卉偏好标签（例如，偏好切花/多肉植物/盆栽植物）和常收礼信息。

4.5.2 产品数据

基本信息：产品 ID（唯一标识符）、花卉名称（例如，“红玫瑰”、“多肉植物组合盆栽”）、花卉类型（鲜切花/盆栽植物/永生花/礼品花束）、价格（原价、促销价）、库存数量（当前可用数量）。

花卉的专业属性：花期（例如，鲜切玫瑰持续7-10天，盆栽百合为多年生），维护难度（简单/中等/困难），适宜环境（温度、光照、湿度要求），花语，原产地可追溯信息（产地、种植基地、采摘时间）。

多媒体数据：主要产品图片（5-8 张），细节图片（展示细节），360°展示视频，维护教程视频（URL 存储）。

分类系统数据：多级分类（例如，“花卉→鲜切花→玫瑰→红玫瑰”），产品标签（新品上市、畅销、节日限定）。

产品规格数据：支持多种规格（如花茎数量、盆径、包装类型），每种规格对应独立的价格和库存。

4.5.3 订单数据

基本信息：订单号（唯一标识符）、用户 ID、订单金额（折扣后的总价）、支付状态（未支付/已支付/已退款）、订单状态（待支付/已支付/准备中/已发货/配送中/已完成/已取消）。

配送信息：期望配送日期、配送时间段、最晚发货时间。

产品信息：产品 ID、购买数量、规格、产品快照（下单时信息备份）。

物流信息：运输地址、物流公司、追踪号码、配送状态。

时间戳：订单时间、支付时间、发货时间、完成时间。

4.5.4 库存数据

实时数据：当前可售库存、锁定库存（预留未支付订单）。

批量数据：批号、存储时间、保质期（针对新鲜切花）、新鲜度等级（A 级/B 级/C 级）。

库存记录：变更类型（入库/出库/退货/损耗）、数量、时间戳、操作员。

警报数据：安全库存阈值、警报通知记录（时间戳、产品 ID、库存数量）。

4.5.5 评估和交互数据

产品评价数据：评分（1-5 星）、评价内容、图片/视频（URL 链接）、商家回复、评价时间戳、用户 ID。

互动数据：评价点赞数、产品收藏记录、问答互动（顾客提问、商家回答）。

专业评价数据：鲜花新鲜度评分、配送包装评分、额外评论。

4.5.6 营销数据

优惠券信息：名称、类型（固定金额/百分比折扣）、面值、使用条件、有效期、发行/使用/剩余数量。

活动数据：活动名称、持续时间、参与产品、表现（订单数量、销售额、收入）。

积分账目数据：变更类型（积分获取/积分兑换/积分过期）、金额、余额、时间戳。

4.5.7 可追溯性数据

原始信息：种植位置的坐标、基地名称、采摘时间、种植过程记录（肥料、浇水、病虫害防治）。

时间线数据：从种植到交付的关键节点（播种/育苗/采摘/运输/交付）及其描述和图片。

4.5.8 知识库数据

维护文章数据：标题、正文、作者、适用花卉、发布时间、阅读量、点赞数。

FAQ 数据：问题、答案、类别（维护/配送/售后）、有用性评分。

季节性特征数据：季节性维护知识、推荐假日花卉主题。

4.5.9 售后数据

工单数据：请求类型（枯萎/损坏/错发商品）、处理进度、用户 ID、订单号、提交时间、支持图片。

处理细节数据：退款金额、负责人、处理时间、结果、用户满意度评分。

问题分析数据：问题分类、交付问题统计、根本原因分析（库存积压/物流粗鲁处理等）。
