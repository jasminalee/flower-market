# 测试工作全局约束条件

## 一、测试用例编写规范

### 1.1 文档结构要求
每个功能模块的测试用例文档必须包含以下2个部分：
1. **模块功能概述**：简要描述该模块的核心功能和业务价值
2. **测试用例表格**：使用标准表格格式详细列出测试用例

### 1.2 测试用例表格格式
严格按照以下字段顺序和格式编写（参考 `测试用例demo.md`）：

| 字段名称 | 说明 | 示例 |
|---------|------|------|
| Test Case ID | 唯一标识符，使用数字编号 | 101, 102, 201 |
| Test Case Title | 简洁明确的测试场景标题，英文句点结尾 | Successful Login. |
| Test Module | 所属功能模块名称，英文句点结尾 | Login. |
| Preconditions | 执行测试前的系统和数据状态 | System has a valid user (admin/admin in database). |
| Input Data | 使用"- "前缀列出所有输入数据 | - Username: admin <br />- Password: admin |
| Steps | 使用数字序号 + `<br />`分隔每个步骤 | 1. Open the login page. <br />2. Enter account and password. |
| Expected Result | 预期结果描述，英文句点结尾 | Login succeeds. |
| Actual Result | 实际执行结果（执行时填写），英文句点结尾 | Login succeeds. |
| Status | 测试状态：Passed / Failed / Blocked | Passed. |
| Priority | 优先级：High / Medium / Low | High |

### 1.3 语言规范
- 测试用例文档全局必须使用英文
